Ход работы

1)	Объяснение работы программы для пользователя

Программа представляет собой локального голосового помощника, который помогает новым студентам лаборатории получать информацию о процессе работы, правилах, инструментах и накопленных знаниях.
Пользователь говорит вопрос в микрофон. Ассистент:
•	распознаёт речь;
•	передаёт текст в большую языковую модель (LLM);
•	получает ответ;
•	зачитывает его голосом.
При этом программа сохраняет историю диалога (память в рамках сессии) и анализирует эмоциональный тон ответа. Все компоненты обработки речи (распознавание и синтез) работают локально на компьютере пользователя. Сама языковая модель подключена через облачный шлюз, но без передачи голосовых данных.

Цель: ускорить ввод новых студентов в рабочие процессы лаборатории, снизить нагрузку на сотрудников и создать единую «точку входа» для типовых вопросов.

2)	Краткая инструкция работы с программой 

1.	Запустите программу → увидите приветствие в консоли
2.	Нажмите Enter → ассистент готов к записи
3.	Говорите в микрофон (можно говорить 2-10 секунд)
4.	Нажмите Enter снова → запись остановится
5.	Дождитесь ответа:
o	🎧 "Распознавание речи..."
o	🧠 "Генерация ответа..."
o	🔊 Ассистент произнесёт ответ вслух
6.	Повторяйте шаги 2-5 для новых вопросов
7.	Для выхода → нажмите Ctrl+C

Горячие клавиши:
1.	Начать/остановить запись – Enter
2.	Завершить программу – Ctrl + C

4)	Порядок работы (по шагам) с объяснением.

Шаг	Действие	Что происходит
1	Запустить программу	Появляется цветное меню в консоли
2	Нажать Enter	Программа начинает запись с микрофона
3	Задать вопрос голосом (2–10 секунд)	Аудио записывается в оперативную память
4	Нажать Enter	Запись останавливается
5	Дождаться обработки	Идёт распознавание → генерация ответа → синтез речи

Важно: Не говорите одновременно с записью ответа ассистента. Дождитесь его полного воспроизведения.

5)	Частые ошибки и их решение
Сообщение / проблема	Решение
«Аудио не записано»	Проверьте микрофон и разрешения приложения
Долгий первый ответ	Нормально: загружаются модели Whisper, Bark, ruBERT
Нет звука из динамиков	Проверьте громкость системы, выберите правильное устройство вывода
Ошибка CUDA out of memory	Используйте bark-small (уже установлен по умолчанию)


6)	Техническая архитектура программы

Модули программы (файлы)
Файл	Назначение	Взаимодействие
main.py	Главный цикл, управление записью/воспроизведением, статистика	Координирует все модули
src/agent.py	Работа с LLM: промпт, история, вызов OpenRouter	Принимает текст пользователя, возвращает ответ
src/stt_service.py	Распознавание речи (Speech To Text) через Whisper	Преобразует аудио → текст
src/tts_service.py	Синтез речи (Text To Speech) через Bark	Преобразует текст → аудио
src/sentiment.py	Анализ эмоциональной тональности ответа	Добавляет метку эмоции в вывод
src/utils.py	Запись с микрофона и воспроизведение аудио	Обёртка над sounddevice
config.yaml	Конфигурация модели для анализа эмоций	Задаёт модель и задачу
uuuu.py	Диагностика CUDA (проверка GPU)	Не участвует в основном цикле

Как хранится и передаётся информация
•	Аудио передаётся между потоками через queue.Queue в виде байтов (bytes).
•	История диалога хранится в оперативной памяти в InMemoryChatMessageHistory (словарь с ключом "voice_assistant_session").
•	Модели кэшируются в папку hf_cache/, чтобы не скачиваться при каждом запуске.
•	Эмоциональный анализ возвращает структуру: label (positive/negative/neutral) и score (уверенность).
Управление потоками
•	Запись аудио выполняется в отдельном потоке (threading.Thread) через callback от sounddevice.
•	Остановка записи — через threading.Event.
•	Основной поток ожидает завершение записи, затем последовательно вызывает STT → LLM → TTS.
Системные требования к работе архитектуры
•	ОЗУ: от 8 ГБ (рекомендуется 16 ГБ)
•	Диск: от 5 ГБ (кэш моделей)
•	GPU (опционально): NVIDIA (CUDA) или Apple MPS для ускорения
•	Сеть: требуется только для вызова LLM (OpenRouter)
